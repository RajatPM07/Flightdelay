# Lessons Learned

## Mock Mode vs. Real Integrations
* **Issue:** Stating that a notification (e.g., a WhatsApp message) was "triggered/delivered successfully" when mock mode (`MOCK_PROVIDERS=True`) was active. Although the system correctly generated database records with status `"sent"` and printed mock output to standard output, it did not dispatch any actual messages to the physical device.
* **Rule:** Always differentiate clearly between mock simulation delivery and real integration dispatch. If a user reports that a message did not arrive on their device, first verify if `MOCK_PROVIDERS` is enabled, and explain that in mock mode, delivery is simulated locally in logs and DB records rather than sent to external APIs (like Twilio).

## A handoff/brief can contradict the artifacts it ships with — trust the artifacts + hard rules
* **Issue:** A pasted "Frontend→Backend integration" brief (auto-generated `Claude Design/Developer Handoff.html` §06) described a **claims/payout** product — `POST /api/claims`, `/api/documents/upload`, `estimatedPayout`, an "airline / insurer / payment processor" status board, `POST /api/leads`. None of it matched reality: the actual shipped HTML screens were monitoring-only (their own footers said *"No money is moved…"*), and `CLAUDE.md` forbids all payout/claim language. Blindly following the brief would have built endpoints that violate the product's hard rules and don't match the frontend.
* **Rule:** When a brief/handoff conflicts with (a) the actual files it references and (b) the repo's hard rules, STOP and reconcile before building. Read the real screens and the real API surface first; map prototypes to endpoints that **already exist** rather than inventing the ones the prose names. Auto-generated handoff prose drifts into generic boilerplate — the code is ground truth.
* **Also:** This repo deliberately has **no build step** (FastAPI serves self-contained HTML). A brief saying "convert to Next.js" is a big architectural change — confirm before adopting a toolchain the repo intentionally avoids. And neutralize payout/claim/compensation wording even in *disclaimers* ("no claim decision is made" still contains "claim").
