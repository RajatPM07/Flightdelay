Edge cases handled by the engine real calls

IATA → ICAO / spacing

Ticket ident (6E1341) maps to FlightAware ICAO (IGO1341); AeroDataBox’s spaced form is normalised.

Flight not found

A bogus ident returns a clean message, not a crash or empty screen.

Future-date / rate-limit

FlightAware’s ~2-day future limit (400) and AeroDataBox’s ~1 req/s (429) surface readable messages.

Gate vs runway / reconciliation

Delay is computed from the best gate-arrival estimate (not runway touchdown); both feeds reconcile to one status.

Reconciliation rules

How the brain resolves two feeds

Deterministic priority — no guesswork, no vendor-specific logic.

Most-progressed state wins

Lifecycle priority landed > cancelled > diverted > departed > delay tiers. If one feed is further along, it wins — a diverging feed is usually just lagging.

Best gate-arrival estimate

Delay is computed from the best gate-arrival estimate (actual_in / estimated_in), never runway touchdown.

Different occurrences refuse to merge

If vendors resolve different legs (date interpreted local vs UTC), the engine detects the >6h spread and declines to reconcile rather than emit nonsense.

Architecture

The data feed is a commodity. The brain is the asset.

Add a third vendor, swap FlightAware for any other provider, or run with one feed only — the decision engine doesn’t change. Only the adapter changes.
